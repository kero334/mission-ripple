# Science mission vertical slice — The Rover Reading

## Data boundary

`tools/build_science_snapshot.py` reads the external science package without modifying it and emits only `src/science/evidence-v1.json`. The public game receives ten direct Curiosity rows, one bounded derived case, finding/event IDs, source URL, original path and source SHA-256. It does not ship the 191 raw files, source manifests, or the first-party portal HTML that contains a public embedded key. The snapshot is versioned and validated by `src/science/mission.ts`; build and QA compare its direct rows against the preserved NASA CSV. The snapshot is immutable during play. A player decision never changes it.

Evidence fields cover ID, mission ID, NASA attribution, source URL, dataset ID, instrument, date, original values and units, derived result, uncertainty, English/Arabic explanation, related decisions, provenance and verification status. New missions should create a new versioned small snapshot with the same fields and an extraction script, then run a source-row comparison.

## Deterministic state

The pure `transition` function in `src/science/mission.ts` accepts only legal stage actions. `localStorage` key `mission-ripple-science-v1` persists stage, decision and the next-shift flag. Invalid save data falls back to a fresh mission. Stages:

| Stage | World action | Result |
|---|---|---|
| ready | Start in mission panel | Nuri briefs the player |
| monitor | Walk to courtyard field terminal, press E | Direct RAD rows and mini chart |
| research | Enter Research Lab, inspect console | Episode analysis, unknowns and source |
| command | Enter Command Hub, inspect console | Schedule one simulated work slot |
| nextShift | Enter Communications, inspect array | Delayed schedule result |
| debrief | Review science explanation | Attribution and boundaries |
| complete | Continue or replay | State remains saved |

The scene emits `ripple-world-interaction` with kind and facility ID. The mission UI consumes it only when the active stage matches. Other buildings and equipment remain explorable. Stage guidance updates the courtyard marker and mission HUD. Scene art, collision, and Nuri movement remain in Phaser; science state and UI remain independent.

## Child-facing visual flow

The mission card uses four visible steps: **See → Understand → Choose → Result**. Each step leads with one original pixel icon and one short takeaway. The field screen shows three selected rover snapshots as bars; Research compares the rounded middle readings for 19 and 20 May and explains that the cause and human dose are unknown. The two illustrated option cards show **now** and **later** effects before a decision. Nuri gives one short prompt at a time. Exact source values, all ten selected rows, IDs, source path, SHA-256 and NASA link remain in a collapsed source drawer for adults or curious children. The main card clearly labels real rover evidence and fictional training choices.

The nine original science icons are generated by `tools/build_science_icons.py` and cataloged in `public/assets/pixel-manifest.json`. No emoji or third-party artwork is used. Radiation data is never converted into a green “safe” or red “danger” status because the package does not provide a human safety threshold.

### Ripple effects

| Decision | Immediate simulated effect | Delayed flag and next-shift effect |
|---|---|---|
| `review-defer` / P2-M02A | Optional robot survey deferred; the one fictional crew-work slot reviews the trend. | `trend_reviewed`: comparison brief ready; survey still pending. |
| `survey-followup` / P2-M02B | Optional robot survey retained; another reading queued. | `followup_reading_due`: the brief keeps an open question until a later reading. |

Both decisions consume one **training-game work slot**, recorded as `simulatedWorkSlotsUsed: 1`. This is a balance variable, not NASA time, outpost power, health, or a physical prediction. Future mission logic may inspect the flag but must not convert it into a dose or safety threshold.

## Scientific limits

The observed May 20 values are rover detector absorbed dose rates in µGy/hour. The package's exploratory 30 µGy/hour line is descriptive, never a human safety limit. The cause is unverified; a DONKI event is not assigned as its cause. Dose equivalent is missing in the export. Personal dosimetry, habitat shielding, calibration flags and local outpost measurement transfer are unavailable. The game does not calculate astronaut dose, health damage, safe duration, or shelter protection. The fictional scheduling exercise is labeled wherever a consequence appears. NASA has not endorsed this game.

## QA and future order

`node tools/science-qa.mjs` compares every chart row with the original CSV and SHA, runs desktop Chrome, tests movement to the field terminal, all mission stages, both choices, reload, replay, Arabic RTL, and zero browser errors. Screenshots and results are in `qa-screenshots/science/`. The portable package validator passed 6,846 checks, but this does not independently certify the scientific interpretation.

Recommended next order: P2-M01 full detector-log audit, P2-M08 missing intervals, P2-M05 plant-control design, then cautious catalog/context missions P2-M03 and P2-M09. Do not build quantitative slope, greenhouse yield, shelter protection, or human-health calculations until their blocked parameters are supplied and reviewed.
