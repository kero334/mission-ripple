# Save state and progress

`src/science/mission.ts` owns `MissionState` version 1 and browser `localStorage` key `mission-ripple-science-v1`. Fields: `stage`, `choice`, `monitorReviewed`, `researchReviewed`, `nextShiftFlag`, `simulatedWorkSlotsUsed`. Legal stages are `ready → monitor → research → command → nextShift → debrief → complete`. Only legal reducer actions advance stage. `review-defer` sets `trend_reviewed`; `survey-followup` sets `followup_reading_due`; both use one fictional work slot. Replay returns initial state and restarts the mission. Save is written on every state transition; reload resumes from it. The NASA evidence JSON is imported/frozen separately and is not modified by choices.

`loadMission` rejects malformed JSON, wrong version, unknown stage or unknown choice; it does **not** validate every boolean/flag/number or cross-field invariant. Treat externally edited saves as a compatibility risk. The first future migration should add full schema validation and tests without silently losing valid saves. World position, visited/inspected sets, dialogue, locale, menu state, inventory preview and camera are memory-only. There is no server save, cloud sync, multi-profile support, XP or campaign-wide progress. QA covers mission save/reload/replay in `qa-screenshots/science/results.json`; it does not establish long-term schema compatibility.
